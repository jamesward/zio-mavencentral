zio-mavencentral
--------------------

[![javadocs.dev](https://www.javadocs.dev/com.jamesward/zio-mavencentral_3/badge.svg)](https://www.javadocs.dev/com.jamesward/zio-mavencentral_3/latest)

A ZIO 2 / Scala 3 toolkit for working with Maven Central:

- **Read API** (`MavenCentral`) — typed `GroupId` / `ArtifactId` / `Version` / `GroupArtifact[Version]` coordinates, `searchArtifacts`, `searchVersions`, `latest` / `latestOrFail`, `pom`, `mavenMetadata`, `isArtifact`, `artifactExists`, `isModifiedSince`, and `jarUri` / `javadocUri` / `sourcesUri` URL resolution. Requests go through `MavenCentralRepo`: repo1 (authoritative) and Google's GCS mirror (`maven-central.storage-download.googleapis.com`, the mirror Central lists itself). Changing metadata (`maven-metadata.xml`) asks repo1 first; published files (jars, POMs) ask GCS first, to keep the bulk of the bytes off repo1, and repo1 when GCS doesn't have them (GCS lags new artifacts by up to a day). Directory listings come from repo1, or GCS's bucket API when repo1 fails. Only repo1's 404 is "not found": a GCS 404 while repo1 can't be asked fails with the temporary `NotFoundOnFallback`. repo1 has a request budget (`RateLimit`, 20/s, burst 50); over it, GCS answers what it can. Each mirror has a failure-rate circuit breaker, and `mavenMetadataIfModified` revalidates with a 304. A 404, or the 400 / 414 Maven Central answers for a path it can't parse (a NUL or invalid UTF-8 in a coordinate, a very long segment), is a typed not-found error; `latestOrFail` reports an unreachable upstream as `LatestUnavailable` instead of dying. `JarCache.mavenCentralDownloader(classifier)` downloads a jar with one GET through this policy, failing as upstream-unavailable if the body stalls for 30 s (`idleTimeout`).
- **Downloads** — stream a jar to a `File` with `downloadJar`, or download-and-extract a zip with `downloadAndExtractZip`, both surfacing `Last-Modified` / `ETag` cache metadata.
- **JarCache** — scoped, on-disk jar cache with random-access `ZipFile` reads, single-flight deduplication of concurrent fetches for the same GAV, and finalizer-driven handle cleanup; entry lookups don't decompress the rest of the jar.
- **GavCacheMiddleware** — `zio-http` `HandlerAspect`s that stamp GAV-versioned routes with a path-derived stable `ETag`, pinned `Last-Modified`, and `Cache-Control: public, max-age, immutable`, and short-circuit conditional GETs to `304 Not Modified` before the upstream fetch.
- **Path codecs** (`MavenCentral.Codecs`) — `zio-http` `PathCodec`s for GAV value types.
- **Publishing** (`MavenCentral.Deploy.Sonatype`) — Sonatype Central Portal client: streaming multipart bundle `upload`, `checkStatus`, `drop`, and an end-to-end `uploadVerifyAndPublish` that polls until the deployment is `VALIDATED` then publishes. Uploads accept `ZStream[Any, Throwable, Byte]` without materializing the bundle (the `Array[Byte]` overload remains for compatibility). `Sonatype.Live` reads `OSS_DEPLOY_USERNAME` / `OSS_DEPLOY_PASSWORD`; `Sonatype.fromCredentials` accepts explicit values.
